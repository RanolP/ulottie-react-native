μLottie on React Native

μLottie is an ahead-of-time Lottie compiler written in Rust. It turns Lottie JSON into a small, self-contained JS module and plays it through one of four React Native renderers: a react-native-svg tree, a @shopify/react-native-skia display list, or a native Rust rasterizer (tiny-skia or ThorVG). This page holds every measurement from the port report — bundle size, native binary size, frame timing, and pixel parity — against the players you would otherwise pick.

The comparison set

Every chart and table below lists these eight players in this order. Rows 1–4 are the existing players; rows 5–8 are μLottie compiler targets. lottie-react-native is the baseline that the original comparison app was built against.

  1. 1lottie-react-native — baseline ~7.3, lottie-ios underneath. Ships the raw JSON plus the lottie-ios native library.
  2. 2Skottie via @shopify/react-native-skia Skia.Skottie.Make(json) + the <Skottie> sksg element, frame driven by useClock. Works on this stack.
  3. 3react-native-skottie (margelo) — incompatible with RN 0.86 new-arch Verified unusable in three steps; the install was reverted. No runtime numbers exist for it. Detail under Compatibility.
  4. 4@lottiefiles/dotlottie-react-native 0.12.1 — compatible with RN 0.86 new-arch LottieFiles' official player, ThorVG underneath. Works bridgeless as published: a Fabric ComponentView on iOS, a Compose DotLottieAnimation view on Android. Its API takes a file source only, so each fixture was wrapped as a .lottie archive.
  5. 5μLottie · rn-svg backend (--target reanimated-aot) Compiles to a react-native-svg element tree driven by a Reanimated useFrameCallback worklet on the UI thread.
  6. 6μLottie · rn-skia backend (--target skia-aot) Compiles to a baked display-list descriptor re-recorded into one native <Canvas> per player through @shopify/react-native-skia.
  7. 7μLottie · rt-thorvg (--target rt) The same scene lowered to RTDL, a renderer-agnostic binary display list, rasterized natively by ThorVG v1.1.1.
  8. 8μLottie · rt-tiny-skia (--target rt) The same RTDL blob rasterized by the pure-Rust tiny-skia CPU backend.

An rn-skia module costs a near-constant ~15.5–17.8 KB raw (~5.5 KB gzip) over its rn-svg twin — the skia runtime (draw-record construction, effects, blend, image handling) is embedded per module today, on top of the shared-runtime inflation already noted for the rn-svg target. The static-fixture floor is ~16.9 KB raw / 6.2 KB gzip (rn-skia) against ~1.2 KB (rn-svg). Sharing the runtime across modules would collapse both floors. This table and the one above were recorded in separate runs; the rn-skia raw column differs by a few hundred bytes between them. Both are reproduced exactly as recorded.

Honest framing of the module-versus-JSON comparison: lottie-react-native ships the raw JSON plus the lottie-ios native library in the app binary, while a μLottie module is the whole payload — self-contained JS with no native rendering dependency beyond react-native-svg/react-native-reanimated, which many apps already carry. Large or keyframe-dense fixtures compress well because the compiler precomputes and dedupes what the JSON spells out per keyframe; small fixtures with animation-heavy content inflate because the fixed runtime worklet code dominates a tiny document.

Performance

All timing numbers on this page come from dev-mode Metro bundles (Hermes, dev=true) on a simulator or emulator. Treat them as relative comparisons, not production absolutes.

Steady state is a tie — on this small fixture. Every player at every instance count holds 60 fps with at most a few dropped frames in ~600, including 16 concurrent looping instances. On a vsync-locked simulator this means "both under 16.67 ms per frame", not "equal cost" — and the heterogeneous mixed16 grid above breaks the tie. lottie-react-native's flat ~17 ms is partly a blind spot: its worst single run was 100 ms at 1 instance, against μLottie rn-svg's 33 ms.

Mount optimization, measured. Two changes landed after the first sweep: an eager runOnUI init warm-up at mount and a once-per-runtime shared cache for the payload decode, easing tables, and arc-length tables, keyed by payload string on the UI runtime's globalThis. Re-sweeping the rn-svg target over {1, 4, 9, 16} × 3 left best-of-3 unchanged within noise (16.7 / 33.1 / 49.5 / 66.7 ms) and improved worst-of-3 at ×16 from 123 ms to 69 ms. Shared-payload decode is therefore not the dominant mount cost; the remaining latency sits in per-instance program bind state plus the Fabric commit of the SVG node tree. A parity spot-check after the change found the new crops pixel-identical to the pre-optimization crops. The cache trades memory for the tail win: one decoded payload per animation persists for the runtime's lifetime. On the rn-skia target a timing probe attributes the same ramp: at ×16, all 16 init() calls together cost ~11 ms on the UI thread (10.6 ms for the first instance's payload decode, ~0.03 ms each for the 15 cache hits) and all 16 first picture records together ~2.7 ms — so the ramp is per-instance Canvas native-view creation, its Fabric commit, and the per-mount runOnUI scheduling round-trips, not worklet work.

Pixel parity

Two different oracles, because the two families are gated differently. The rt backends diff directly against lottie-web at 512² in CI. The rn-svg target diffs against lottie-react-native screenshots from the compare app, since that is the baseline it was built to match.

rt backends against lottie-web — 17 fixtures, gated in CI

cargo test -p ulottie-rt --features "tinyskia thorvg" runs the full 17-fixture corpus at 5 pins per fixture for both backends — 34 tests, all passing. A pixel counts as different past 25/255 on any channel; the default budget is 1% of pixels per frame. Two fixtures carry a documented wider budget, both structural divergences rather than bugs. Every other fixture × frame × backend holds the 1% default.

Divergences between the two references are documented, not chased.

tiny-skia node budget — a warning, not a refusal

A scene past ~500 display-list nodes compiles with a named WARNING (stderr plus a module comment) instead of a refusal: past that budget tiny-skia at 512² cannot hold 60 fps on a phone, measured, and ~2000 nodes is infeasible. Correctness stays a refusal; the budget is advisory. The mixed16 result above is the warning in practice — rt-tiny-skia sits at 32.5 ms per frame with bodymoovin's 1381 nodes in the load, while rt-thorvg holds 16.8 ms.

@lottiefiles/dotlottie-react-native 0.12.1 — compatible with RN 0.86 new-arch

LottieFiles' official ThorVG-based player runs on this stack as published, verified on both platforms with all 16 mixed16 cells rendering. iOS registers a Fabric ComponentView (plus a legacy-interop fallback); Android wraps a Compose DotLottieAnimation view. No config change was needed on this app: its Expo config plugin only raises the iOS deployment target to 15.4 (this app is at 16.4) and defaults useFrameworks: dynamic, which proved unnecessary — the vendored dynamic frameworks embed fine in a static-linkage Pods build via plain pod install.

  • The API takes a file source only. source accepts a require()'d asset or a URL, never a JSON object or string (parseSource routes through Image.resolveAssetSource). Every fixture was therefore wrapped into a minimal .lottie zip (manifest.json plus animations/<id>.json) and Metro's assetExts gained lottie.
  • Android was measured with the default software renderer. Its GL renderer is opt-in and is not measured on this page.
  • Rendering runs off the probed thread, the same caveat class as lottie-react-native — the frame probe sees the React commit and the induced UI-thread load, not the player's own rasterization.

react-native-skottie (margelo) — incompatible with RN 0.86 new-arch

Verified in three steps, then the install was reverted. It is not patchable without forking.

  • Duplicate Skia copy. Its latest release 2.1.4 (last publish 2024-05-06) hard-depends on @shopify/react-native-skia ^1.2.3, so installing it beside the app's 2.10.x nests a duplicate 429 MiB Skia copy.
  • Android build fails at configuration. Its android/build.gradle hard-wires dependsOn ':react-native-reanimated:prepareHeadersForPrefab', a reanimated 3.x internal task that reanimated 4's worklets split removed.
  • C++ includes stale internal headers. It includes rn-skia 1.x internals (RNSkPlatformContext.h, the JsiSk* wrapping API) whose layout changed in rn-skia 2.x.

@shopify/react-native-skia's own Skottie module does work on this stack (RN 0.86, new architecture) and is the comparison baseline used throughout this page.

Android: the rn-svg target did not finish

Two attempts at the mixed16 load, two distinct upstream crashes: a Hermes VM SIGSEGV (null dereference inside libhermesvm.so on the main thread) while mounting the 16 SVG trees, then a react-native-svg Fabric prop-cast RedBox (java.lang.String cannot be cast to java.lang.Double in RNSVGGroupManagerDelegate.setProperty). The ~2200-node mixed16 SVG commit is beyond the rn-svg player on Android; the rt players render the same content from the same compiler frontend without touching the view tree.

Nested <Svg> flattening is deliberate

react-native-svg mounts a native RNSVGSvgView per <Svg>, and that breaks the emitted tree twice: each view keeps its own brush/mask/filter registry, so url(#id) inside a nested <Svg> never resolves to the root <Defs>; and the iOS blend path sizes its offscreen mask buffers from the nested view's rect in parent user units while rendering with the full device CTM, so an up-scaling outer viewBox paints every masked subtree empty. Flattening to one root <Svg> with viewport-clipped <G>s leaves one native view with correctly sized buffers and one document-global registry.

rn-skia deviations from the web target

  • The tint effect's luminance matrix is specified in linearRGB (color-interpolation-filters); Skia has no per-filter colorspace, so it runs in sRGB. Visually close, not bit-equal.
  • SVG filter regions on effects are ignored: the drop shadow's 0%/100% region (a lottie-web self-box clip quirk) and the blur's widened region have no Skia counterpart on a layer filter, and neither is needed for correct output.
  • An effect stage re-draws its input once per pass (SVG's primitive chain as nested saveLayers), so tint costs three content redraws. Correctness first; a flattened single-pass form is an optimization left open.

Measurement conditions. Every timing number on this page comes from dev-mode Metro bundles (Hermes, dev=true) running on the iPhone 17 simulator (iOS 26.4, locked 60 Hz vsync) or an arm64 Android AVD (android-35, 60 Hz) — relative comparisons, not production absolutes. The Android sweeps B and C each ran while another emulator occupied the same host CPU, so their absolute numbers are inflated and only within-table comparison is meaningful. Bundle-size numbers come from npx expo export:embed --dev false over minimal entry points; JS-bundle deltas exclude native binaries, which the native binary section measures separately. The compare app is Expo SDK 57, React Native 0.86, new architecture; the baseline is lottie-react-native ~7.3 with lottie-ios underneath.
