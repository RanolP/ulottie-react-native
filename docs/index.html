Net installation size

What a player really costs an app: its native binary plus the gzipped JS it adds. Native size is per-platform, so iOS and Android are charted separately; the JS segment is identical on both. Skottie by margelo was measured in a separate RN 0.74 old-arch app — cross-app comparison is indicative only.

Performance

The load is mixed16: 16 distinct heavy fixtures mounted at once (node sum 2281), 10 s probe, median of 3. The rn-svg player mounts only the 12 it can compile (node sum 2185). iOS is an iPhone 17 simulator; Android is an arm64 AVD (android-35, 60 Hz). All timings come from dev-mode Metro bundles. Read them as relative, not as production absolutes.

iPhone 17 simulator, boucing_ball, 10 s probe, best of 3. This sweep predates the rt targets, Skottie and dotlottie, so it covers three players only; "baseline (no player)" is the probe itself.

Where the mount ramp comes from

A shared payload-decode cache left rn-svg best-of-3 unchanged (16.7 / 33.1 / 49.5 / 66.7 ms) and cut worst-of-3 at ×16 from 123 ms to 69 ms. On rn-skia at ×16, the 16 init() calls cost ~11 ms together (10.6 ms is the first decode, ~0.03 ms each for the 15 cache hits) and the 16 first picture records ~2.7 ms. The ramp is per-instance native-view creation, not decode.

Pixel parity

Two pixel oracles, one per family: the rt backends diff against lottie-web at 512² in CI, the rn-svg target against screenshots of the player it was built to match.

rt backends — 17 fixtures × 5 pins × 2 backends, gated in CI

34 tests, all passing. A pixel differs past 25/255 on any channel; budget 1% of pixels per frame, with two fixtures on a wider documented budget.

The two documented budget exceptions

fx_effects, both backends, 3%. lottie-web's 0%/100% filter region clips the drop shadow to the element's own box; the rt rasterizer drops percentage filter regions and draws the real After Effects shadow. Worst frame: 2.657%.

image_embedded, thorvg only, 3.5%. ThorVG's texture mapper bilinear-filters across the picture's outer edge — a ~1-texel feather band, wide at this fixture's 32× upscale. Frame 0 passes at 0.002%.

rn-svg target — 12 fixtures × 5 pins, screenshot oracle

Each fixture pinned at 0/25/50/75/100% of its frame range, 300×300 dp crops at @3x (900 px), diffed with odiff against a ≤1% gate. 59/60 cells pass; 1 is a documented divergence.

rn-skia parity sweep: pending. The capture scripts predate that player and need a _s crop pass first.

External images have no loader inside a self-contained worklet module; expressions have no engine on any RN target. react-native-svg supports neither paint-order nor mix-blend-mode. Inverted track mattes (tt: 2/tt: 4) compile on rn-svg behind --allow track-matte-inverted — SVG filters inside masks are the least-trodden react-native-svg path, so the finding stays gated.

tiny-skia node budget — a warning, not a refusal

Past ~500 display-list nodes a scene compiles with a named WARNING: tiny-skia at 512² cannot hold 60 fps on a phone beyond that, and ~2000 nodes is infeasible. mixed16 is the warning in practice — rt-tiny-skia sits at 32.5 ms per frame with bodymoovin's 1381 nodes in the load, rt-thorvg at 16.8 ms.

dotlottie 0.12.1 — runs on RN 0.86 new-arch

The baseline player works as published on both platforms, all 16 mixed16 cells rendering, with no config change.

  • File sources only. source takes a require()'d asset or a URL, never JSON. Each fixture was wrapped into a minimal .lottie zip and Metro's assetExts gained lottie.
  • Android used the default software renderer. Its GL renderer is opt-in and unmeasured here.
  • Rendering runs off the probed thread, so the frame probe sees the React commit and induced UI-thread load, not the player's own rasterization.
iOS packaging fine print

Its Expo config plugin only raises the iOS deployment target to 15.4 (this app is at 16.4) and defaults useFrameworks: dynamic, which proved unnecessary — the vendored dynamic frameworks embed fine in a static-linkage Pods build via plain pod install.

react-native-skottie (margelo) — legacy stack only, incompatible with RN 0.86 new-arch

Verified in three steps, then reverted. Not patchable without forking. It runs on a legacy stack only, so it was measured separately in examples/compare-legacy — RN 0.74.1, old architecture, react-native-skottie 2.1.4, rn-skia 1.2.3, reanimated 3.10.1. Those numbers carry its charted rows above, marked (legacy app); cross-app comparison is indicative only.

  • Duplicate Skia copy. Release 2.1.4 (published 2024-05-06) hard-depends on @shopify/react-native-skia ^1.2.3, nesting a duplicate 429 MiB Skia beside the app's 2.10.x.
  • Android build fails at configuration. android/build.gradle hard-wires dependsOn ':react-native-reanimated:prepareHeadersForPrefab', a reanimated 3.x task that reanimated 4 removed.
  • Stale C++ includes. It includes rn-skia 1.x internals (RNSkPlatformContext.h, the JsiSk* API) whose layout changed in 2.x.

@shopify/react-native-skia's own Skottie module does run on this stack.

Android: the rn-svg target did not finish

Two attempts at mixed16, two upstream crashes: a Hermes VM SIGSEGV (null dereference in libhermesvm.so) while mounting the 16 SVG trees, then a react-native-svg Fabric prop-cast RedBox (java.lang.String cannot be cast to java.lang.Double in RNSVGGroupManagerDelegate.setProperty). A ~2200-node SVG commit is beyond that player on Android.

Two implementation notes

Nested <Svg> is flattened on purpose. Each native RNSVGSvgView keeps its own registry, so url(#id) never resolves to the root <Defs>; and the iOS blend path sizes mask buffers from the nested view's rect, so an up-scaling outer viewBox paints masked subtrees empty. One root <Svg> with clipped <G>s fixes both.

rn-skia deviations from the web output. The tint matrix runs in sRGB, not linearRGB — visually close, not bit-equal. SVG filter regions on effects are ignored; neither is needed for correct output. An effect stage re-draws its input per pass, so tint costs three content redraws.

How we measured

  • App. Expo SDK 57, React Native 0.86, new architecture. Baseline player: @lottiefiles/dotlottie-react-native 0.12.1.
  • Bundle size. npx expo export:embed --dev false over minimal entry points (examples/compare/bench/e0..e9), Hermes-targeted minified JS, boucing_ball as the one animation. Deltas exclude native binaries.
  • Timing. Dev-mode Metro bundles (Hermes, dev=true), 10 s useFrameCallback UI-thread probe, 3 runs per player, median per metric, on the iPhone 17 simulator (iOS 26.4, locked 60 Hz) or an arm64 AVD (android-35, 60 Hz). Relative comparisons, not production absolutes.
  • mixed16. The 16 heaviest distinct fixtures mounted at once. rn-svg mounts 12 of them: fx_effects, gradient_animated, blend_multiply and matte_luma_inv are skia-only in the app registry.
  • Parity. cargo test -p ulottie-rt --features "tinyskia thorvg" for the rt backends; odiff over @3x screenshot crops for rn-svg.
